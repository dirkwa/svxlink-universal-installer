# Web dashboard (opt-in)

The stack can serve the
[SvxLink Dashboard V4 by CN8VX, radioprj fork](https://github.com/radioprj/SvxLink-Dashboard-V4.0-by-CN8VX)
— a PHP status page showing node activity, EchoLink/reflector state, the
live log, and host temperature. It is **not installed by default**:

```bash
svx dashboard install          # or SVX_DASHBOARD=1 at bootstrap
```

`svx dashboard status`, `update`, and `remove` manage it afterwards.

## License: why the image is built on your machine

The dashboard's upstream tree is published **"All rights reserved"** (its
README badge). That means we may not redistribute it — neither the source
nor a container image built from it. What an operator may do is fetch the
public repository and run it privately. So `svx dashboard install`:

1. clones the fork into `~/.svxlink/dashboard-src/`,
2. checks out the pinned commit (below),
3. builds `localhost/svxlink-dashboard:local` with podman — the image
   exists only on your host and is never pushed to any registry,
4. writes the `svxlink-dashboard.container` Quadlet and starts it.

SvxLink itself (GPL) and the voice packs (GPL-2.0) are unaffected — only
the dashboard has this constraint.

## Pinned upstream commit

Third-party code that runs unauthenticated on your LAN never floats: the
build always checks out one reviewed commit, and the pin only moves through
a release of this installer (picked up via `svx self-update`, applied via
`svx dashboard update`).

Pinned commit: `d344a2c0b0887c5b51dd23e877e0689cd2458d4e`

This SHA is duplicated as the `DASHBOARD_PIN` constant in
`installer/linux/svx.tmpl`; CI (`check-dashboard-pin-sync.sh`) fails if the
two ever differ, so this document is always the truth about what gets
built.

## Security: no authentication, LAN only

The dashboard has **no login**. By default it binds `0.0.0.0:8080` so
phones and shack PCs on your LAN can reach it. **Never port-forward it to
the internet** as-is — if you want it public, put an authenticating reverse
proxy in front and set `SVX_DASH_BIND=127.0.0.1` (or answer `127.0.0.1` at
the install prompt) so only the proxy can reach it. Choosing port 80
additionally writes `/etc/sysctl.d/80-svxlink-unprivileged-ports.conf`
(rootless processes may then bind 80; the file's existence records your
consent).

## What the dashboard can and cannot read

Everything it shows is derived from read-only mounts:

| In container | From host | Why |
|---|---|---|
| `/var/log/svxlink` (ro) | `~/.svxlink/log/` | The entire data source: the svxlink log file and its single `.1` rotation sibling. |
| `/etc/svxlink/svxlink.conf` (ro) | `~/.svxlink/etc/svxlink.conf` | Callsign/logic parsing. Contains no secrets. |
| `/etc/svxlink/svxlink.d/ModuleEchoLink.conf` (ro) | `~/.svxlink/dashboard/ModuleEchoLink.conf` | A **sanitized copy** — see below. |
| `/var/www/html/include/{config,dash_config}.php`, `talkgroups.json` (ro) | `~/.svxlink/dashboard/` | Your dashboard configuration. |
| `/sys/class/thermal` (ro) | host | CPU temperature tile. |

**The sanitized EchoLink copy**: your real
`~/.svxlink/etc/svxlink.d/ModuleEchoLink.conf` contains the EchoLink
password in plaintext (an svxlink requirement) and stays mode 0700,
outside the container. The dashboard instead gets
`~/.svxlink/dashboard/ModuleEchoLink.conf`, a copy with the `PASSWORD=`
value replaced by `REDACTED`, regenerated by `svx dashboard
install`/`update` and whenever `svx config` touches the original. An
unauthenticated web app never has the credential on its filesystem.

## Configuration

Seeded **only if absent** into `~/.svxlink/dashboard/` — after that the
files are yours; hand edits survive every rebuild and update:

- `config.php` — title, QTH, frequencies, sysop, theme/language defaults,
  timezone (pre-filled from your install answers).
- `dash_config.php` — refresh interval, QRZ lookup links.
- `talkgroups.json` — talkgroup number → display name map (seeded with a
  tiny example set; extend to match your reflector).

Edit and reload the page — the files are bind-mounted, no restart needed.

## Update / remove

- `svx dashboard update` — re-fetches the clone, checks out the (possibly
  new) pin, rebuilds the image, restarts. A failed build leaves the running
  dashboard untouched (the `:local` tag only moves on success).
- `svx dashboard remove` — stops the unit, removes the Quadlet (snapshot
  first) and the local image; your `~/.svxlink/dashboard/` configs are
  preserved for a later reinstall.
